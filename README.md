# ربات پایش ارزش آپارتمان‌های دیوار (تهران)

این ابزار به‌صورت خودکار و رایگان (روی GitHub Actions، بدون نیاز به روشن بودن
لپ‌تاپ یا گوشی تو) آگهی‌های «خرید آپارتمان» دیوار در تهران را در بازه قیمتی
تعیین‌شده بررسی می‌کند، قیمتِ هر متر هر آگهی را با میانه‌ی آگهی‌های مشابه
مقایسه می‌کند، و فقط آگهی‌هایی که **نسبت به ارزش واقعی‌شان ارزان‌تر هستند** را
به تلگرام شما اطلاع می‌دهد — نه همه‌ی آگهی‌های آن بازه قیمتی.

## این چطور کار می‌کند

به‌جای نوشتن یک خزنده‌ی تازه برای دیوار، این پروژه از
[`divar-mcp`](https://github.com/sepehr071/divar-mcp) استفاده می‌کند؛ یک
پروژه‌ی متن‌باز (MIT) و فعال که همان API عمومیِ خودِ سایت دیوار را، با
درخواست‌هایی شبیه به کروم واقعی و با سرعت محدود و مسئولانه، صدا می‌زند و
ابزارهایی برای پیدا کردن «آگهی‌های زیر میانه‌ی قیمت» و «بهترین ارزش در یک
بودجه» دارد — دقیقاً همان چیزی که برای این پروژه لازم بود. اسکریپت
`divar_watch.py` این ابزار را مستقیماً (بدون واسطه‌ی هوش مصنوعی) صدا می‌زند.
با تشکر از سازنده‌ی آن، سپهر رادمرد (github.com/sepehr071).

هر ۲ ساعت یک‌بار (قابل تغییر)، یک GitHub Action:

1. دسته‌ی «خرید و فروش آپارتمان» را روی دیوار پیدا می‌کند.
2. در بازه قیمتی و متراژ `config.yaml` جستجو می‌کند (در کل تهران یا فقط
   محله‌های دلخواه تو).
3. با دو ابزار `dv_find_deals` و `dv_best_for_budget` از `divar-mcp`،
   آگهی‌هایی را پیدا می‌کند که قیمتِ-هر-متر‌شان به‌طور محسوسی پایین‌تر از
   میانه‌ی آگهی‌های مشابه است.
4. برای هرکدام، جزئیات کامل آگهی را می‌خواند تا پارکینگ/انباری/آسانسور/سند
   تک‌برگ/طبقه را تشخیص دهد.
5. فقط آگهی‌هایی که قبلاً ندیده (در `state/seen_tokens.json` ثبت نشده) را به
   تلگرام می‌فرستد و آن‌ها را ثبت می‌کند تا دوباره تکراری اعلام نشوند.

## راه‌اندازی (یک‌بار)

### ۱. ساخت ربات تلگرام

1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بده و `/newbot`
   را بزن. یک نام و یک نام‌کاربری (باید به `bot` ختم شود) انتخاب کن.
2. BotFather یک **توکن** می‌دهد شبیه `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxx`
   — نگهش دار.
3. به ربات تازه‌ساخته‌ات یک پیام (مثلاً `سلام`) بده تا چت باز شود.
4. برای گرفتن **chat_id** خودت، این آدرس را در مرورگر باز کن (به‌جای
   `<TOKEN>` توکن بالا را بگذار):
   `https://api.telegram.org/bot<TOKEN>/getUpdates`
   در خروجی JSON دنبال `"chat":{"id": ...}` بگرد؛ همان عدد chat_id توست.

### ۲. ساخت مخزن روی گیت‌هاب

1. یک ریپازیتوری تازه (می‌تواند Private باشد) در گیت‌هاب بساز.
2. تمام فایل‌های این پوشه را در آن push کن:
   ```bash
   git init
   git add .
   git commit -m "initial commit"
   git branch -M main
   git remote add origin https://github.com/<username>/<repo-name>.git
   git push -u origin main
   ```

### ۳. تنظیم Secrets

در صفحه‌ی ریپازیتوری: **Settings → Secrets and variables → Actions → New
repository secret** و این دو را اضافه کن:

| نام | مقدار |
|---|---|
| `TELEGRAM_BOT_TOKEN` | توکنی که از BotFather گرفتی |
| `TELEGRAM_CHAT_ID` | chat_id که بالا پیدا کردی |

### ۴. اولین اجرای تستی

به تب **Actions** برو، روی workflow با نام «Divar value watch» بزن، سپس
**Run workflow** (با `verbose_summary` روی `true`، که پیش‌فرض هم همین است) را
بزن. بعد از حدود یک دقیقه:

- اگر همه‌چیز درست باشد، یک پیام در تلگرامت می‌آید (حتی اگر آگهی جدیدی پیدا
  نشده باشد، چون verbose_summary روشن است).
- اگر مشکلی پیش آمد، روی اجرای workflow کلیک کن و لاگ مرحله‌ی «Run watcher»
  را ببین — اسکریپت دلیل خطا و (در صورت نیاز) خروجی خام دیوار برای عیب‌یابی
  را همان‌جا چاپ می‌کند.

از این به بعد، بدون هیچ کاری از طرف تو، این workflow هر ۲ ساعت خودش اجرا
می‌شود و فقط وقتی آگهی ارزشمند تازه‌ای پیدا شد، در تلگرام پیام می‌دهد.

## داشبورد HTML (رابط کاربری)

علاوه بر پیام‌های تلگرام، هر بار که ربات اجرا می‌شود یک فایل `dashboard.html`
هم می‌سازد و در همان ریپازیتوری commit می‌کند. این فایل یک رابط کاربری کامل
و مستقل است (نیازی به اینترنت یا سرور ندارد) که همه‌ی آگهی‌های ارزشمندِ
فعلاً دیده‌شده را نشان می‌دهد و امکانات زیر را دارد:

- جستجو در عنوان/محله، فیلتر بر اساس محله، حداقل درصد ارزانی
- فیلتر سه‌حالته برای پارکینگ، انباری، آسانسور، سند تک‌برگ (دارد/ندارد/فرقی نکند)
- مرتب‌سازی بر اساس ارزشمندترین، قیمت، قیمت هر متر، یا تازه‌ترین
- یک بخش «تنظیمات» که در خودِ مرورگر یک `config.yaml` تازه می‌سازد و دانلود
  می‌کند — یعنی می‌توانی بازه قیمت، محله‌ها یا فیلترهای الزامی را از توی
  همین صفحه تغییر بدهی، فایل دانلودشده را جایگزین `config.yaml` کنی، و
  commit/push بزنی

**چطور ببینمش؟**

- ساده‌ترین راه: فایل `dashboard.html` را از ریپازیتوری (یا از پوشه‌ای که
  GitHub Actions آن را commit کرده) دانلود کن و با دوبار کلیک در مرورگر
  (کروم، فایرفاکس، سافاری) باز کن. چیزی نصب نمی‌شود و نیازی به اینترنت هم
  نیست؛ همه‌چیز در یک فایل است.
- اگر می‌خواهی بدون دانلودِ هر بار، از گوشی هم به آخرین نسخه‌اش دسترسی
  داشته باشی: در تنظیمات ریپازیتوری **Settings → Pages**، از شاخه‌ی
  `main` و پوشه‌ی `/ (root)` را به‌عنوان منبع انتخاب کن. بعد از چند دقیقه
  آدرسی شبیه `https://<username>.github.io/<repo-name>/dashboard.html`
  فعال می‌شود که همیشه همان نسخه‌ی تازه‌ی ریپازیتوری را نشان می‌دهد (توجه:
  اگر ریپازیتوری Private باشد، GitHub Pages فقط در پلن‌های Pro/Team فعال
  می‌شود؛ برای حالت رایگان روی Private repo همان دانلود دستی فایل کافی‌ست).

قبل از اولین اجرای موفق ربات، یک نسخه‌ی نمونه (با آگهی‌های ساختگی، فقط برای
نشان دادن شکل صفحه) همراه این پروژه است. برای ساختن دوباره‌ی آن به‌صورت
دستی (یا بعد از تغییر `config.yaml` بدون اجرای کامل ربات):

```bash
python dashboard.py            # از روی state/listings.json واقعی می‌سازد
python dashboard.py --sample    # با داده‌ی نمونه، فقط برای پیش‌نمایش ظاهر
```

## تنظیم فیلترها (`config.yaml`)

فایل `config.yaml` را باز کن؛ هر بخش کامنت فارسی دارد. مهم‌ترین‌ها:

- `price.min_toman` / `price.max_toman` — بازه قیمتی (الان ۴ تا ۶ میلیارد).
- `min_area_m2` — حداقل متراژ (الان ۵۰).
- `districts` — اگر خالی باشد کل تهران رتبه‌بندی می‌شود؛ برای محدود کردن به
  چند محله: `districts: ["شهرزیبا", "پونک"]`.
- `min_discount_pct` — چقدر باید ارزان‌تر از میانه‌ی قیمتِ-هر-متر باشد تا
  «ارزشمند» حساب شود (عدد بالاتر = هشدارهای کمتر ولی سخت‌گیرانه‌تر).
- `require.parking` / `require.storage` / `require.elevator` /
  `require.single_sheet_deed` — اگر `true` بگذاری، آگهی‌های بدون آن ویژگی
  حذف می‌شوند؛ با `null` فقط در پیام نمایش داده می‌شود ولی فیلتر نمی‌کند.

بعد از هر تغییر در `config.yaml`، فقط commit و push کن؛ اجرای بعدی خودش
تنظیمات تازه را می‌خواند.

## اگر روزی پیام‌ها قطع شد

- **خطای «challenge» یا بلاک شدن:** دیوار گاهی صفحه‌ی تایید ربات نشان
  می‌دهد. در `requirements.txt` خط اول را به `divar-mcp[browser]>=0.3.0`
  تغییر بده، و در `.github/workflows/watch.yml` مرحله‌ی کامنت‌شده‌ی
  «Install headless browser fallback» را فعال کن (کامنت `#` را بردار).
- **دیوار ساختار API را عوض کرده:** چون این یک API رسمی و مستند نیست،
  ممکن است در آینده کمی تغییر کند. اسکریپت طوری نوشته شده که به جای حدس
  زدن کورکورانه‌ی ساختار دقیق پاسخ، خودش هر بار دسته‌بندی را پیدا می‌کند و
  در صورت خطا، خروجی خام را در لاگ Actions چاپ می‌کند؛ اگر تشخیص خودکار دسته
  اشتباه شد، می‌توانی اسلاگ درست را در `config.yaml` زیر `category_override`
  دستی بگذاری.
- برای دیدن نسخه‌ی به‌روز `divar-mcp` و مستندات کامل آن:
  https://github.com/sepehr071/divar-mcp

## هزینه

رایگان. GitHub Actions برای ریپازیتوری خصوصی ماهانه ۲۰۰۰ دقیقه رایگان
می‌دهد؛ این workflow هر اجرا حدود ۱ تا ۲ دقیقه طول می‌کشد و هر ۲ ساعت یک‌بار
اجرا می‌شود (حدود ۷۰۰ دقیقه در ماه)، یعنی کاملاً داخل سهمیه‌ی رایگان است.
